### N1. Uncached correlation requests still get a 504 from nginx

**Where:** reverse proxy configuration (not in the repo); `CorrelatesPanel.tsx:117,148`.

A first `/correlations/family` request for a combination that is not cached returns `504 Gateway Time-out` after 60 s (reproduced live, kegg K00001 vs cog). The panel retries up to 12 times with a 10-minute client timeout, and the server keeps scoring under a per-family lock, so the user eventually gets a result. The 60 s cut-off is the only reason the retry loop exists.

**Verify:** an uncached family request returns 200 on the first attempt, or the panel documents the retry as the intended mechanism.

## 3. Correlation finder

### CR2 (remaining). The false-positive rate is about 6%, not 5%

**Where:** `tests/test_correlation_math.py:393-424`.

With the effective-N test, 5.8–6.0% of independent AR(1) pairs (φ = 0.85, n = 128) have corrected p ≤ 0.05 for every coefficient; the test accepts up to 7%. Benjamini-Hochberg across the family still controls the FDR, so this is a caveat for the Methods page rather than a defect.

**Verify:** the Methods page states the measured per-pair rate, or the test bar is brought to 5%.

### N3. The correlation cache is not invalidated when the p-value method changes

**Where:** `correlations_cache` is keyed on `(catalog_id_a, catalog_id_b, metric, method)` (`FastAPI/scripts/create_sql_schema.py:194`). The p-value procedure changed twice in November (`e686f75`, `39f4d76`) without changing the key. `invalidate_correlations_cache` exists (`migrate_annotations_to_sql.py:215`) but only the migrations call it.

A live spot check on 2026-11-03 (psbA K02703 vs enzyme, three pairs recomputed locally) matched the current code exactly, so the cache was cleared by hand at this deploy. Nothing enforces that next time.

**Fix:** add a method-version column to the key, or a documented deploy step.
**Verify:** after a change to `score_pair`, a cached pair's p-value equals a fresh computation.

### N4. Cross-source correlations can be partly by construction

The same gene can carry a KEGG, COG and EC annotation, and `norm_egc` is compositional (every value is a share of one per-sample total). Neither is mentioned in the panel or on the Methods page.

**Verify:** the Methods page says what a cross-source correlation can and cannot mean.

## 6. Licensing (not a correctness issue)

### N6. KEGG BRITE content is redistributed in source and by the API

KEGG is "an original database product, copyright Kanehisa Laboratories"; its legal page asks academic users who provide services with KEGG to obtain an academic service provider licence.

- `frontend/src/constants.ts:130`, `KEGG_BRITE_CODES`: 449 pathway and category codes with their `ko00001.keg` names, committed and shipped in the public JS bundle. No generator script is committed.
- The public API serves the full BRITE and EC hierarchies with names (`/kegg/children`, `/kegg/path`, `/kegg/parents`, enzyme routes) and `/series/export` writes them into CSVs (`routes.py:964-965`, `lineage` column).
- The `.keg` files and database are not in the repo.

**Verify:** a decision is recorded on the service-provider licence, and KEGG names are served from the database rather than embedded in source.
