## 2.1 Stored data (notebooks)

### E17. COGs in several NCBI categories are counted in only one (High)

**Where:** `Notebooks/EGC_COG_TREE.ipynb`, cell 5 (`cog_map = {cog_id: … for cat, cog_dict in cogs.items() …}`) and cell 9 (a single `_register(cat_letter, …)` per gene). The same single letter is written to the leaf's `parent_id` and to `cog_paths`.
**Confidence:** Confirmed (executed). Live data, built with the same `cog_map` code, stores COG0028 under H.

**What's wrong:**

- NCBI lists a COG on every one of its categories' pages. COG0028, for example, appears on both E and H.
- `cog_map` is a dict keyed by COG id, so the last page in URL order wins (J A K L B D Y V T M N Z W U O X C G E F H I P Q R S).
- Rebuilding `cog_map` from the same 26 NCBI pages gives exactly the 5,061 entries printed by the notebook. 400 of those COGs belong to more than one category.

**Examples:**

| COG | NCBI categories | Counted under | EGC in 3300060358 that is missing from the other categories |
|---|---|---|---|
| COG0028 | E, H | H | 11,413 |
| COG0697 | E, R | R | 44,782 |
| COG0477 | G, E, P, R | R | 49,423 |
| COG0745 | K, T | T | 25,755 |

Share of each category's signal that is missing:

| Category | Missing |
|---|---|
| A | ~40% |
| D | ~36% |
| N | ~33% |
| V | ~31% |
| K (Transcription) | ~24%; 58 of its 224 COGs |
| E | ~21% |

21 of the 26 categories are affected.

The notebook run on synthetic data shows the mechanism. Take two genes on one scaffold (coverage 10): one with COG0028 (E, H) and one with COG0031 (E). The stored value is E = 10. The correct value is E = 20.

**Fix:** keep every letter per COG, register each gene under every letter (the per-node gene set already prevents double counting), and write one `cog_paths` row per (letter, COG). Correct `AboutPage.tsx:300`.
**Verify:** in any sample, the gene set of category E includes the genes of COG0028, COG0697 and COG0477. `cog_paths` has one row per NCBI (letter, COG) membership, not one row per COG.

### E18. Genes with a partial EC number ("3.6.1.-") are dropped from their EC class (Medium, Conditional)

**Where:** `Notebooks/EGC_ENZYME_TREE.ipynb`, cell 9 (`if ec_id not in brite: dropped_ec_ids.add(ec_id); continue`).
**Confidence:** Confirmed (executed). The size of the effect depends on how many real genes carry partial ECs; the previous audit counted 135 distinct partial ids.

**What's wrong:**

- The comment says KEGG's EC file "only lists fully-resolved leaves". That is not true: the parent nodes 3.6.1, 3.6 and 3 are all in the file.
- A gene labelled `EC:3.6.1.-` should still count toward its sub-subclass, subclass and class. Instead it is dropped from all three.

**Example:**

- Synthetic run: gene A has EC 3.6.1.23 and gene B has EC 3.6.1.-. The stored nodes 3.6.1, 3.6 and 3 contain {A} only. The correct content is {A, B}.
- Live data: KOs whose only EC is partial carry about 22% of the signal of class 3 (Hydrolases), and about 8% of classes 1 and 7.
- Large cases include K07263 pqqL [EC:3.4.24.-] with a mean EGC of 11,390, and K03924 moxR [EC:3.6.3.-] with 9,657.

**Fix:** strip trailing `.-` components and start the upward walk at the deepest resolved node.
**Verify:** node 3's EGC rises by the summed EGC of genes whose EC contains "-" under class 3.

## 2.2 Correlation finder

### CR8. The `circular_shift` null contains the real alignment, so true correlations fail and noise passes (High, for that method)

**Where:** `FastAPI/api/correlation_sql.py:289-341` (`_circular_shift_pvalue`).
**Confidence:** Confirmed (executed), independently by two reviewers.

**What's wrong:**

1. Shifts are drawn from 1 to n−1. When a shift s equals one of the lags searched (±1, ±2, ±3, ±6), the lag search re-creates the original pairing. So 8 of the 127 possible shifts are near-copies of the observed data, and a real correlation can never get a p-value below about 0.03–0.06.
2. `p = count / n_perm` can be exactly 0, which shows as q "<.001".
3. Shifts where no lag can be scored stay in the denominator. This makes p too small for sparse series.
4. With 128 samples there are only 127 distinct shifts, so drawing 1,000 random shifts suggests more precision than the test has.

**Examples:**

- A perfect copy of the reference gets p = 0.031. The same copy lagged by 2 samples gets p = 0.063, which is not significant.
- Family simulation with 30 true correlates (ρ = 0.8) and 270 null candidates (AR(1) with φ = 0.85): the method reported 3 significant results. All 3 were null candidates with p = 0, and 0 of the 30 true correlates were found.
- Second run, with 12 real pairs (r ≈ 0.93) among 60 candidates: 0 were significant (q = 0.16–0.20). With the fix described below, all 12 are significant (q = 0.005).

The panel presents this method as the statistically defensible choice.

**Fix:** enumerate exactly the shifts with max|lag| < s < n − max|lag|, compute p = (1 + #extreme) / (1 + #evaluable), and leave unscorable shifts out. The smallest possible p is then about 1/116, which cannot survive BH across a family of about 3,400 candidates. For large families, use phase-randomised surrogates or an effective-sample-size correction.
**Verify:** a noisy copy of a series gets the minimum possible p regardless of the seed, and no shift of 6 or less contributes to the null.

### CR9. Strain-level taxonomy references are correlated against their own ancestors (Medium)

**Where:** `correlation_sql.py:179-217` (`get_family_candidates`).
**Confidence:** Confirmed (executed), independently by two reviewers.

**What's wrong:**

- The ancestor walk looks up each parent in `by_id`, which only holds candidates of depth ≤ 6 (`TAXONOMY_DEPTH_CUTOFF`).
- For a strain (depth 8), the walk excludes the species (depth 7) and then stops, because the species is not in `by_id`.
- The strain's genus, family, order, class, phylum and domain all stay in the family, and each of them contains the strain's own genes.

**Example:** the family for `…;Vibrio cholerae;Vibrio cholerae O1` against taxonomy returns:

- **Vibrio** (genus), r = 0.891, q = 1.5e-42
- Vibrionaceae, r = 0.79
- Vibrionales, r = 0.64
- Gammaproteobacteria, Proteobacteria and Bacteria further down

The same request for the species returns none of them. The panel says "siblings/ancestors/descendants excluded".

**Fix:** exclude every `;`-prefix of `ref_annotation_id`.
**Verify:** for a depth-8 reference, no returned id is a prefix of the reference id.

### CR10. Results are silently capped at 50 (Medium)

**Where:** `CorrelatesPanel.tsx:81-87` sends no `limit`, and the backend default is 50 (`correlation_sql.py:459`). Neither the panel legend nor `AboutPage.tsx:173-175` ("only candidates with q < 0.05 are shown") mentions a cap.
**Confidence:** Confirmed (code).

**Example:** with the default method, an enzyme family of about 3,400 candidates yields far more than 50 rows with q < 0.05 (see CR2). The user sees exactly 50 and takes that as the whole significant set.

**Fix:** return the total number of significant results and show "top 50 by |r| of N significant".
**Verify:** the panel shows the total significant count, or an explicit note about the cap.

### CR11. The correlation cache can return another pair's r after the catalog is rebuilt (Conditional)

**Where:** `correlations_cache` is keyed on `annotation_catalog.id`. `migrate_annotation_catalog_sql.py` does a DELETE and re-insert, and ids restart at 1. Only the annotations migration clears the cache, and it runs *before* the catalog rebuild.
**Confidence:** Conditional. The mechanism is confirmed (executed); it depends on the order the scripts are run in.

**Example:** add one annotation that sorts early, then rebuild the catalog. The cached pair (K00001, Bacteria) with r = 1.0 is then served as (enzyme "1", K00002) with r = 1.0, q = 0. Computed fresh, that pair gives r = −0.15, p = 0.83. The docstrings of the path migration scripts tell people to re-run the catalog rebuild on its own, which is exactly the order that triggers this.

**Fix:** clear `correlations_cache` inside `populate_annotation_catalog`, or key the cache on (source, annotation_id).
**Verify:** after a catalog rebuild, `SELECT COUNT(*) FROM correlations_cache` returns 0.

## 2.3 API and charts: missing samples, nested sums, formatting

### W21. Samples where an annotation wasn't detected don't show up anywhere (High)

This finding does not assume any value for the undetected samples. It is only about what the app displays.

**Where:**

- `annotation_series` has rows only for samples where an annotation was detected, and the API returns only those rows.
- Two consumers present that result as if it covered every sample:
  - (a) **Charts:** `EgcChart.tsx:112-128` builds points only from the rows returned, so the line runs straight from one detection to the next, across any stretch of non-detections. `MultiEgcChart.tsx:271` also sets `connectgaps: true`. The header at `EgcChart.tsx:430` reads "X of Y samples", where Y is the number of rows returned, not 128.
  - (b) **Catalog means:** `migrate_annotation_catalog_sql.py:44-47` averages over the detected samples only. The UI labels this value "Mean EGC … static aggregate across all timepoints" and never shows how many samples it comes from. It feeds `/search/annotations`, the lookup card, the date-filtered Top EGC path (`cache_sql.py:638-641`) and the search-result ranking.

**Confidence:** Confirmed (live).

**Examples:**

- K02570 is detected in 63 of 128 samples. Its non-detections come in blocks rather than scattered: 25 in a row from 6/7 09:00 to 6/11 17:00. That is far more clustered than a random placement would give (runs test z = −5.9). The chart draws one straight line across those four days at the level of the detected values, so a long period with no detection looks like steady presence.
- K01427 is detected in 70 of 128 samples. The header reads "Relative Abundance · 70 of 70 samples", and the 58 samples without a detection are not mentioned anywhere.
- "Streptomyces phage Lika" has a catalog mean EGC of 335.1 from 9 samples, presented as an aggregate across all timepoints. It ranks #170 in a "phage" search, above 71 phages detected in all 128 samples. Nothing tells the user that one mean comes from 9 samples and the others from 128.
- 1,389 of 2,500 sampled KEGG annotations are undetected in at least one sample.

**Fix:**

- (a) Break the line wherever the annotation wasn't detected. Add a null point for each undetected timepoint and set `connectgaps: false`; a null means "no value", so no value is invented. Show "detected in N of 128".
- (b) Label the catalog value "mean when detected", show the detection count next to every mean, and let users sort or filter by detection count.

**Verify:** the K02570 chart has a gap from 6/7 to 6/11, its header reads "63 of 128", and search rows show a detection count next to the mean.

### W22. Summing annotations that contain one another double-counts them (High)

**Where:**

- (a) The default Scaffold Information chart: `ScaffoldExplorePanel.tsx:191-217` loads the top 10 annotations as suggested terms, `:168` sets `splitByTerm = false`, and `:95-114` and `:442-447` add them into one "All terms (10)" line.
- (b) Analyze "∑ Group": `AnalyzePage.tsx:928-975`, which feeds GroupedEgcChart, the Compare drawer and `ComparePage.tsx:249-250`.

Nothing checks whether one member contains another. W19 added exactly this check for taxonomy exclusions, but not for sums.
**Confidence:** Confirmed (executed), with live values.

**Examples:**

- (a) The live top 10 taxonomy annotations form one nested chain: Bacteria ⊃ Proteobacteria ⊃ Alphaproteobacteria ⊃ Rhodobacterales… At 5/27 13:00, Bacteria has 198,368 scaffolds, Proteobacteria 119,648 and Alphaproteobacteria 57,894. With just these three, the chart shows **375,910**; the true distinct count is 198,368. With all ten the total is several times too high. KEGG (09180 ⊃ 09182 ⊃ 02000) and Enzyme (2 ⊃ 2.7) behave the same way. The subtitle reads "sum across all annotations".
- (b) Search "Rhodobacter" (97 hits, all within Rhodobacterales), Select all, then ∑ Group (the group takes the first 20). The summed mean EGC is 9.69e6, 2.2× the order's own 4.40e6. The summed Relative Abundance is **0.538** against the true 0.246. The chart says 54% of all gene copies are Rhodobacter-related; the truth is 25%.

**Fix:** when adding terms to a sum, detect ancestor/descendant pairs (taxonomy `;`-prefix; KEGG, EC and COG parent paths). Drop the descendants or refuse the group with a message. Open Scaffold Information split by term.

### W27. The smoothing slider mostly does nothing, and smoothed values are presented as the data (Medium)

**Fix:** use a bandwidth in hours (or a range of 0.1–0.8), include the window's end points, compute statistics from the unsmoothed values, and label smoothed tooltips.
**Verify:** at the lowest slider setting, more than 0 points change, and toggling smoothing does not change the statistics.
